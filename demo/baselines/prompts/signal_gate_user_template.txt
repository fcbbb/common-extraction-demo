Validate candidate file groups for extractable shared components.

Input JSON:
{payload}

For every candidate return exactly one object in the same order. Each object:
{
  "candidate_id": "c0",
  "groups": [
    {
      "members": ["file_000.py", "file_004.py"],
      "shared_concept": "short description of the shared component",
      "shared_interface": [
        {"name": "helper_name", "signature_guess": "helper_name(...)", "role": "one sentence"}
      ],
      "key_variations": ["..."]
    }
  ]
}

Rules:
- A candidate is a mechanically-grouped set of files that MAY contain one shared
  component, several distinct components, a shared framework abstraction, or none.
  Use baseline discovery's broad notion of reusable algorithmic behavior; literal
  duplication is not required when files implement the same coherent protocol or
  abstraction with meaningful variations.
- Always inspect subsets. If a candidate is mixed, split it and return every valid
  subgroup instead of rejecting the whole candidate. A group may contain only a
  subset of the candidate's members.
- Return one group per reusable behavior/component you find (usually 0 or 1).
- members of each group must be a non-empty subset of the candidate's listed
  members with at least 2 files; groups must be disjoint; every file not listed
  in any group is treated as noise.
- Reject (empty groups) only when the overlap is merely generic I/O boilerplate,
  imports, method signatures, comments, logging, or trivial glue without shared
  algorithmic behavior or a reusable framework abstraction.
- Also reject a group when the shared implementation is too small to pay for one
  common definition plus the import/call-site edits in every member file. If the
  expected token saving is non-positive, return no group even when the code is
  semantically related. A semantic-only similarity signal is not enough by
  itself to justify extraction.
- Use a conservative judgment: when unsure whether the shared component is large
  enough to reduce executable tokens, reject it rather than forcing extraction.
- The files within one candidate are listed in the "files" array; use those ids.
- Output valid JSON only. Do not wrap it in markdown.
